# Design: M2 — Device catalog in the web portal

## Context

M1 delivered ingestion, the `sites`/`devices`/`measurements` schema and the azd/Terraform foundation. See [proposal.md](proposal.md) for motivation and `specs/` for behaviour. This design applies ADR-0005 (passwordless), ADR-0007 (authorization and API exposure) and ADR-0008 (IaC/regions), and the API conventions of the [implementation guidelines](../../../docs/architecture/implementation-guidelines.md).

## Goals / Non-Goals

**Goals:**
- A reusable API foundation (security, errors, OpenAPI, APIM import) that M3–M6 extend.
- A portal shell and design system that later milestones extend with pages.

**Non-Goals:**
- Measurements/charts (M3), sites/certificates management (M4), thresholds/alerts (M5), assistant (M6).
- Group-based or per-site authorisation.

## Decisions

### D1. Entra app registrations (Terraform `azuread`)
- `sdp-api-<env>`: identifier URI `api://<appId>` (the format Entra accepts without a verified domain; set after creation since the app id is only known then), app roles `DeviceData.Read` and `DeviceData.Write` (allowed member types: User), delegated scope `user_impersonation`, `requested_access_token_version = 2`; service principal with `app_role_assignment_required = false`, so users without a role still obtain a token, `GET /me` answers `canRead: false` and the portal shows the access-denied page; every data operation refuses them with 403. Optionally (variable, dev only) the Azure CLI client is pre-authorized on the API scope so operators can test with `az account get-access-token --scope api://…/user_impersonation`.
- `sdp-web-<env>`: SPA platform with redirect URIs (SWA default hostname, `http://localhost:5173`), required resource access to the API scope, pre-authorized on the API.
- Deployer user assigned both roles (`azuread_app_role_assignment`); optional variables for group object ids.

### D2. Device API service
- `services/device-api`: Spring Boot 4, Spring MVC on virtual threads, Spring Security OAuth2 resource server (issuer `https://login.microsoftonline.com/<tenant>/v2.0`, audience = API client id), role mapping from `roles` claim → authorities; `DeviceData.Write` granted both authorities.
- Data access with `JdbcClient` and hand-written SQL (simple, transparent for the demo); passwordless datasource via Spring Cloud Azure.
- Entity tag = hash of the editable fields and `updated_at` (not `xmin`: ingestion updates `last_seen_at` every few seconds, which would make every edit fail with 412); `PATCH` uses JSON Merge Patch semantics with an allow-list of fields, `If-Match` required (428 when missing), row locked (`SELECT … FOR UPDATE`) between the tag check and the update.
- Attribution: `updated_by` = editor object id and `updated_by_name` = display name (new column, migration V3).
- Permissions: `@RequiredRole(AUTHENTICATED|READ|WRITE)` on handlers, enforced by an MVC interceptor from `platform-common` that refuses platform handlers without the annotation (fail closed); the same annotation produces `x-sdp-required-role` in the OpenAPI document.
- Problem details via Spring's `ProblemDetail`; OpenAPI 3.0 (the version API Management imports) generated by springdoc and exported to `services/device-api/openapi.json` by a unit test that fails on drift (`-Dsdp.openapi.update=true` regenerates it); the document is not served at runtime.
- Container app with external ingress (required for APIM v2 without VNet), min 1 replica for demo responsiveness.
- DB grants (Flyway migration): `SELECT` on sites/devices/measurements/metric_definitions; `UPDATE(display_name, description, location, updated_at, updated_by)` on devices.

### D3. API Management
- `azurerm_api_management` Basic v2 (`var.apim_sku`, default `BasicV2_1`), system-assigned identity, Application Insights logger using managed identity (no instrumentation key).
- Tier choice: Basic v2 provides every gateway capability the platform needs through M6: `validate-azure-ad-token`, `cors`, `rate-limit-by-key`, managed-identity Application Insights logging and unbuffered response streaming for the agent (M6). Standard v2 only adds outbound VNet integration with network-isolated backends, inbound private endpoints and higher included request volume; none is needed because backends are reachable over public ingress (ADR-0008) and demo traffic is low. Switching to `StandardV2_<n>` is an in-place SKU update via `apim_sku`.
- One API `sdp-api` at path `api/v1`, imported from `openapi.json`, backend = device-api container app FQDN. Later milestones add operations or APIs for other backends under the same path prefix (`/api/v1/sites/*/certificates` → provisioning-api, `/api/v1/agent/*` → agent).
- Policies (product/API level): `validate-azure-ad-token` (tenant, audience; no client-application restriction so forwarded tokens and test clients work), an operation-level policy fragment declaring the required role of each operation (generated from an `x-sdp-required-role` OpenAPI extension) checked against the `roles` claim, CORS for the SWA origin and localhost, `rate-limit-by-key` per `oid`, forwarding of `traceparent`. Policy XML lives in `infra/modules/api/policies/` as templates.

### D4. Web portal
- `web/portal`: React 19 + TypeScript + Vite, **Fluent UI React v9** (Microsoft look & feel, accessible components), `@azure/msal-react` (auth code + PKCE, redirect flow), TanStack Query for data fetching/caching, React Router with URL search params as state for filters.
- `GET /api/v1/me` drives role-aware UI (`canWrite`), never token parsing.
- Runtime configuration (`clientId`, `tenantId`, `apiScope`, `apiBaseUrl`) generated into `public/config.json` by an azd `prepackage` hook from azd env values — the same build artefact works for all environments.
- `staticwebapp.config.json`: SPA navigation fallback, security headers (CSP restricting `connect-src` to APIM and Entra endpoints).
- Tests: Vitest + React Testing Library for components; Playwright smoke test against a deployed environment using a test user.

### D5. Static Web App
`azurerm_static_web_app` Free tier in `var.web_location` (`eastus2`; `westeurope` is blocked by tenant policy); azd service `web` with `host: staticwebapp`; no SWA built-in auth or linked backend (ADR-0007).

## Risks / Trade-offs

- [ACA ingress publicly reachable] → backends validate tokens and roles (spec "Gateway bypass"); ingress IP restrictions can be added if APIM gets a static IP later.
- [Role-less users can obtain tokens for the API] → harmless: every data operation requires a role (gateway and backend); only `/me` answers them.
- [APIM Basic v2 provisioning time (~5–15 min)] → acceptable; created in parallel with other resources.
- [CORS/CSP mismatch between environments] → origins derived from Terraform outputs, never hard-coded.

## Migration Plan

Additive: new resources and a new Flyway migration; no change to M1 data. Rollback by redeploying previous images; app registrations are retained unless `azd down`.
