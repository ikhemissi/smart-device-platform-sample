# Security model

How the demonstrator implements [ADR-0005](adr/ADR-0005-passwordless-identity.md) (passwordless identity), [ADR-0006](adr/ADR-0006-device-identity-per-site-ca.md) (device identity) and the `platform-security` spec. Reversible details live in the [implementation guidelines](architecture/implementation-guidelines.md) §4 and §7.

## Workload identities

Each workload runs with its own user-assigned managed identity and only the roles it needs (Terraform: [`infra/rbac.tf`](../infra/rbac.tf), [`infra/modules/ingestion`](../infra/modules/ingestion/main.tf)).

| Identity | Access |
|---|---|
| `id-decoder-*` | Event Hubs Data Receiver (hub `device-telemetry`), Storage Blob Data Contributor (container `checkpoints`), Monitoring Metrics Publisher (Application Insights), PostgreSQL role `sdp_ingest` |
| `id-simulator-*` | Key Vault Secrets User (demo site CAs), Monitoring Metrics Publisher |
| `id-migrator-*` | PostgreSQL Entra administrator (schema owner), Monitoring Metrics Publisher |
| `id-acr-pull-*` | AcrPull (image pulls for all container apps and jobs) |
| IoT Hub (system identity) | Event Hubs Data Sender (hub `device-telemetry`) |
| Deployer (user running `azd`) | Key Vault Secrets Officer, Device Provisioning Service Data Contributor, IoT Hub Data Contributor (bootstrap, troubleshooting); PostgreSQL Entra administrator and firewall rule for its IP (dev only, `deployer_is_user`, `allow_deployer_ip`) |

Container apps receive `AZURE_CLIENT_ID` (not a secret) to select their identity. The Application Insights connection string only locates the resource: local authentication is disabled, so ingestion requires an Entra token (`APPLICATIONINSIGHTS_AUTHENTICATION_STRING=Authorization=AAD;ClientId=…`).

## Local authentication disabled

| Service | Setting |
|---|---|
| PostgreSQL Flexible Server | `password_auth_enabled = false` (Entra only) |
| Event Hubs | `local_authentication_enabled = false` |
| Storage (checkpoints, Terraform state) | `shared_access_key_enabled = false` |
| Key Vault | RBAC authorization (no access policies) |
| Application Insights | `local_authentication_enabled = false` |
| Container Registry | admin user disabled, anonymous pull disabled |

## Devices

Devices authenticate with X.509 certificates issued by their site CA; DPS enrollment groups (one per site) use X.509 attestation only — no symmetric keys. Demo site CAs are generated by `scripts/bootstrap-demo-sites.sh` and stored in Key Vault (`site-<siteId>-ca`); production sites would use the customer's PKI.

## Documented exceptions

| Exception | Why | Containment |
|---|---|---|
| **DPS → IoT Hub link** uses the IoT Hub shared access policy `dps-link` | DPS cannot link to IoT Hub with an Entra identity | IoT Hub local auth stays enabled for this purpose only. The connection string is passed by Terraform from resource to resource, marked sensitive, never output, never configured on any workload. |
| **Terraform state** may contain sensitive attributes (e.g. the DPS link) | Terraform stores resource attributes | Remote state in a storage account with shared keys disabled, Entra-authenticated (`use_azuread_auth`), access limited to deployers. |
| **Static Web Apps deployment token** (from M2) | Required by the Static Web Apps deployment API | Fetched at deploy time by azd with the deployer's Entra identity; never stored. |
| **Demo site CA private keys** in Key Vault, readable by the simulator | The simulator issues device certificates on the fly | Demo only; Key Vault RBAC limits read access to the simulator identity and the deployer. |

## Tenant governance

Some tenants' policies force public network access to *Disabled* on Storage and Key Vault, or apply other controls, unless resources carry specific tags. As ADR-0008 uses public endpoints protected by Entra authentication, set the tags your tenant requires in the azd environment (`azd env set RESOURCE_TAGS "key=value,key=value"`): they are applied to every resource, the resource groups and the Terraform state, and never stored in the repository. Local authentication remains disabled everywhere.

## Verifying

```bash
azd env get-values                                     # no key, password, SAS token or connection string
terraform -chdir=infra output                          # same (after `terraform init` with the azd backend config)
az role assignment list -g "$(azd env get-value AZURE_RESOURCE_GROUP)" -o table
```
